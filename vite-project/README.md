# Канбан-доска

## 1. Назначение проекта

Веб-приложение «Канбан-доска» предназначено для визуальной организации задач по методологии Kanban.  
Приложение позволяет создавать задачи, перемещать их между колонками и отслеживать статус выполнения в реальном времени.  
**Цель:** упростить управление личными и командными задачами, повысить прозрачность процесса и минимизировать потерю задач.

## 2. Общие сведения

- **Тип приложения:** одностраничное веб-приложение (SPA)
- **Целевая аудитория:** разработчики, студенты, небольшие команды
- **Платформа:** веб-браузеры (Chrome 120+, Firefox 115+, Safari 17+, Edge 120+)
- **Версия:** 1.0 (март 2026)
- **Разработчик:** littleviil

## 3. Функциональные требования

**FR-1. Просмотр доски**  
Пользователь видит 5 колонок в фиксированном порядке:

- «Без статуса»
- «Нужно сделать»
- «В работе»
- «Тестирование»
- «Готово»

**FR-2. Создание задачи**

- Обязательные поля: заголовок (3–100 символов), описание (текст).
- Опционально: дата дедлайна (формат ДД.ММ.ГГГГ).
- После создания задача автоматически попадает в колонку **«Без статуса»**.
- При нарушении ограничений выводятся сообщения:  
  • «Заголовок должен содержать от 3 до 100 символов»  
  • «Описание не может быть пустым»

**FR-3. Перемещение задач**  
Пользователь может перетаскивать задачу между колонками (drag-and-drop мышью и touch). Состояние сохраняется автоматически.

**FR-4. Редактирование и удаление**

- Клик по задаче открывает форму редактирования.
- Кнопка «Удалить» полностью удаляет задачу.

**FR-5. Сохранение данных**  
Все задачи автоматически сохраняются в localStorage. При перезагрузке страницы данные полностью восстанавливаются.

**FR-6. Навигация**

- Главная страница — доска (маршрут `/`).
- Дополнительная страница — настройки темы.

**FR-7. Темизация**  
Поддержка светлой и тёмной темы.

## 4. Нефункциональные требования

- Время отклика на drag-and-drop ≤ 100 мс
- Совместимость: последние 2 версии основных браузеров
- Доступность: контраст ≥ 4.5:1 (WCAG AA)
- Ограничение хранения: не более 500 задач
- Данные хранятся только на стороне клиента (без сервера)
- Адаптивный дизайн (мобильные устройства ≥ 320 px)

7. Глоссарий

Task — задача (id, title, description, status, deadline)
Column — колонка (статус: «Без статуса» / «Нужно сделать» / «В работе» / «Тестирование» / «Готово»)
Drag & Drop — механизм перетаскивания задач
localStorage — браузерное хранилище задач

8. Требования к тестированию

Smoke-тесты (открытие доски, создание задачи)
Функциональные тесты (drag-and-drop, сохранение)
Негативные тесты (пустой заголовок, слишком длинный текст)
Граничные значения (заголовок 3 и 100 символов)
